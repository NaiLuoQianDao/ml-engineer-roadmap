## Concepts
什么是 Edge Case？
- 边缘情况，指程序在极端或非典型输入下的表现。比如空列表 `[]`、最大/最小数值、输入为空等。这些情况平时不常发生，但一旦发生最容易让程序崩溃。

什么是 Boundary Value Analysis？
- 边界值分析。因为程序错误最容易发生在输入范围的“边界”上。例如及格线是 60 分，那么 59、60、61 就是最需要测试的边界值。

Boundary Case 与 Invalid Input 的区别：
- Boundary Case（边界情况）通常是**合法输入**，只是处于临界点（例如分数为 0 或 100）。
- Invalid Input（无效输入）是**不合法的输入**（例如分数输入为字符串 "abc"，或者人数为负数）。今天主要练习前者，Day 10 会学后者。

## Exercise 01

哪个输入最容易发现错误？
-`60`。如果函数里的判断写成了 `> 60` 而不是 `>= 60`，这两个测试立刻就会报错，从而帮我们抓出 Bug。

## Exercise 02
函数的作用：
- `count_above_threshold(numbers, threshold)`：统计列表中**严格大于**阈值的数字个数。

至少六条测试及预期结果：
1. `[70,80,90], 60` -> `3` （正常情况）
2. `[], 60` -> `0` （空列表边界）
3. `[60], 60` -> `0` （等于阈值边界，因为条件要求严格大于）
4. `[59,60,61], 60` -> `1` （跨越阈值的三个相邻边界）
5. `[-3,-1,0,2], 0` -> `1` （包含负数与零的边界）
6. `[80,80,80], 80` -> `0` （全部刚好等于阈值的边界）

## Mini Project
实现了哪些功能？
- 实现了 `count_passing` 统计及格人数。
- 实现了 `calculate_pass_rate` 计算及格率。
- 用 `main` 函数将逻辑串联，并写入了 7 条测试用例（包含全过、全挂、单元素、空列表等）。

为什么空列表需要特殊处理？
- 计算及格率的公式是 `及格人数 / 总人数`。如果传入空列表，总人数为 `0`，会导致**除以零错误（ZeroDivisionError）**使程序崩溃。所以在 `calculate_pass_rate` 中必须先用 `if scores:` 检查，如果为空则直接返回 `None`。
